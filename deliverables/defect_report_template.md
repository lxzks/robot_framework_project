## 1. 问题描述（一句话说清是什么错）

水温超过 120℃ 后，仪表水温报警灯在 **13 秒**才点亮，规范要求 **≤5 秒**（含 2 个诊断周期确认）。

## 2. 复现步骤（必须可复现 —— 这是缺陷单的核心）

```
前置：ECU 以 coolant=125 启动，系统上电稳定
1. 用诊断仪确认系统进入正常工况（无故障码）
2. 等待水温从 90℃ 爬升至 120℃ 以上（约 15 秒）
3. 用秒表/Trace 记录"水温首次超过 120℃"到"水温灯点亮"的时间差
4. 重复 3 次
```

**复现率**：3/3（必现）

## 3. 实际结果 vs 期望结果

| | 内容 |
|---|---|
| **期望** | 水温超限后 ≤5 秒内点亮水温报警灯（规范 SRS-7.3.1） |
| **实际** | 13 秒后才点亮；实测三次：13.2s / 12.8s / 13.5s |
| **数据** | 见附件 Trace：`bus_trace_bug0417.asc`（CANoe 可直接打开） |

## 4. 分析（提缺陷前自己先做的功课 —— 让你和开发对话平等）

```
时间线（来自 Trace）：
  T+0.0s   水温首次 > 120℃（0x100 报文）
  T+0.2s   P0116 状态 = pending（0x59 响应确认）
  T+0.4s   P0116 状态 = confirmed  ← 故障确认只有 1 个周期？
  T+13.1s  0x300 报文里 CoolantTempHigh 位首次置 1  ← 灯晚了 12.7 秒
结论：DTC 确认正常（0.4s），但"confirmed → 点亮灯位"这一步延迟了 12.7 秒。
      怀疑是警告灯位图的计算周期问题，或 DTC→Telltale 的联动逻辑放在了
      较慢的周期任务里。
```

**为什么这段最值钱**：它把"你看到的现象"和"开发要查的地方"连起来了。
开发拿到这份报告可以直接定位，而不是从零复现。
