# D2 · 写第一个"自动化测试"（60 分钟）

> **今天的目标**：让电脑**自动**检查一件事，然后告诉你"通过"或"不通过"。
>
> 昨天你是用眼睛看仪表；今天你让电脑替你看。

---

## 先说清楚："测试"到底是什么？

**用生活打比方**：你在网上买了一台电视，收到货先做一件事 —— **通电看看亮不亮**。

这就是测试：**拿一个"应该是什么样"的标准，去对比"实际是什么样"**。

```
标准：电视应该能开机
实际：按了电源键，屏幕亮了
结论：通过 ✓
```

**自动化测试** = 把这件事写成**代码**，让电脑替你重复做。

```
标准：车速应该在 50~70 之间
实际：电脑读到 62.3
结论：通过 ✓
```

**就这么简单。** 今天你先写一个"假"的（不连车），明天再连真的。

---

## 第 1 步：新建一个文件

### 什么是"文件"

就是电脑里的一个文档。你要写一个**特定格式**的文件，后缀名是 `.robot`。

### 怎么建

在你的项目文件夹里（`robot_framework` 这一层），新建一个文本文件，命名为：

```
my_first.robot
```

> 💡 **Windows 小技巧**：在文件夹空白处右键 → 新建 → 文本文件 →
> 把它改名成 `my_first.robot`（如果系统提示"改扩展名可能不可用"，点"是"）
>
> 💡 **Mac**：用"文本编辑"新建，保存时选"纯文本"，文件名写 `my_first.robot`

### 打开它，输入这 3 行

**一字不差地**输入下面内容（注意：第 2、3 行前面有**空格**，第 3 行前有 **4 个空格**）：

```
*** Test Cases ***
检查车速是不是合理
    Log    你好，车载测试
```

> ⚠️ **格式极其重要**，这是新手第一个大坑：
> - 第 1 行 `*** Test Cases ***` **顶格写**，前后不能有空格
> - 第 2 行是"测试的名字"，**顶格写**
> - 第 3 行是"具体做什么"，**开头必须有 4 个空格**（这是"缩进"，表示它属于上面那个测试）

---

## 第 2 步：跑起来

回到终端（在项目文件夹里），输入：

```bash
python -m robot --outputdir results my_first.robot
```

按回车。

**你应该看到**：

```
============================================================
My First
============================================================
检查车速是不是合理                                          | PASS |
------------------------------------------------------------
My First                                                    | PASS |
1 test, 1 passed, 0 failed
```

**看到 `PASS` 和 `1 test, 1 passed, 0 failed` —— 恭喜你，你写出了第一个自动化测试！** 🎉

> 💡 它其实**什么都没检查**（`Log` 只是打印一句话）。
> 但你已经跑通了"写代码 → 执行 → 看结果"这个循环。

---

## 第 3 步：让它"真的检查点东西"

现在把文件改成这样（把原来的内容替换掉）：

```
*** Test Cases ***
检查车速是不是合理
    ${speed}=    Set Variable    60
    Should Be True    ${speed} > 50
```

**逐行解释**（不用背，看懂就行）：

| 这行 | 什么意思 |
|---|---|
| `${speed}=    Set Variable    60` | 把数字 60 存进一个叫 `speed` 的"盒子"里 |
| `Should Be True    ${speed} > 50` | 检查 `60 > 50` 对不对。对 → PASS，不对 → FAIL |

再跑一次：

```bash
python -m robot --outputdir results my_first.robot
```

**还是 PASS** ✓（因为 60 确实大于 50）

---

## 第 4 步：故意让它失败（很重要，别跳过）

把最后一行改成 `> 100`：

```
    Should Be True    ${speed} > 100
```

再跑。**你会看到**：

```
检查车速是不是合理                                          | FAIL |
Evaluating expression '60 > 100' failed.
```

**看到 FAIL 不用慌 —— 这正是我们要的。**

> 🎯 **为什么要故意失败一次？**
> 因为**你以后 70% 的时间都在看失败信息**。
> 你现在就要习惯："失败不是坏事，失败是电脑在告诉你哪里不对。"

---

## 第 5 步：让失败信息"说人话"

现在的问题是：失败时只显示 `60 > 100 failed` —— **不够清楚**。

改成这样（加一个 `msg=`）：

```
    Should Be True    ${speed} > 100    msg=车速 ${speed} 太低了，应该大于 100
```

再跑，**你会看到**：

```
车速 60 太低了，应该大于 100
```

**这就清楚了**：一眼知道"实际是多少、期望是多少"。

> 💡 **这条是本项目的铁律**：所有断言都要写 `msg=`，把实际值带上。
> 因为三个月后的你（或者你的同事）看到失败信息时，需要马上知道发生了什么。

---

## ✅ 今天的验收标准

1. 你能**不看文档**，自己新建一个 `.robot` 文件
2. 跑出一次 `PASS`，再跑出一次 `FAIL`
3. 能说清：**`${speed}=` 那行在干什么**、**`Should Be True` 在干什么**
4. 能说清：**为什么断言要加 `msg=`**

---

## 🆘 卡住了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `Parsing error` / 语法错误 | 格式不对（最常见） | 检查：第 1 行是否顶格、第 3 行是否有 **4 个空格** |
| `No keyword with name 'xxx' found` | 关键字名拼错了 | 对照本文抄；注意 `Should Be True` 有空格 |
| `1 test, 0 passed, 1 failed` | 断言条件不成立 | 这可能是**对的**（你故意改的），看失败信息 |
| 找不到 `my_first.robot` | 文件不在项目根目录 / 后缀名不对 | 确认文件在 `robot_framework` 这一层；确认后缀是 `.robot` 不是 `.robot.txt` |
| `command not found: robot` | 没在项目环境里 | 确认第 1 步 `cd` 到项目了；或先跑 `python training/check_all.py` 验证环境 |

> 💡 **格式问题占新手错误的 80%**：RF 靠"缩进"来判断层级，
> 多一个空格少一个空格都可能报错。**出问题先看空格。**

---

## 📌 今天你学到的事

1. **测试 = 拿"期望"对比"实际"**，通过就 PASS，不通过就 FAIL。
2. **自动化测试 = 把这件事写成代码**，让电脑重复做。
3. **失败信息要写清楚**（`msg=`），因为你会看它几百次。
4. `.robot` 文件的格式规则：`***` 顶格、测试名顶格、步骤缩进 4 个空格。
