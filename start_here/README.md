# 从这里开始：7 天，从"完全不懂"到"能跑出一个测试"

> **这套东西是给谁写的？**
> 给**从来没接触过汽车、没开过车、也没写过自动化测试的人**。
>
> 你不需要懂：
> - 汽车（不需要驾照，不需要知道发动机怎么工作）
> - 编程（不需要会 Python）
> - 测试（不知道什么是"测试用例"也没关系）
>
> 你只需要**会打字、会开网页、会用鼠标**。剩下的，这 7 天我一步步带你做。

## 开始前的 3 件事（5 分钟）

### ① 找到"终端"（就是那个黑框框）

- **Windows**：按 `Win` 键 → 输入 `git bash` → 回车（如果你装过 Git）；
  或者按 `Win` + `R` → 输入 `cmd` → 回车
- **Mac**：按 `Command + 空格` → 输入 `terminal` → 回车

你打开后会看到一个**黑色（或白色）的窗口，里面有一行字和一个闪烁的光标**。
这个东西叫"终端"（Terminal），**你以后所有命令都在这里输入，输完按回车**。

> 💡 不要怕它。它不会因为你打错一个命令就坏掉 —— 大不了重来。

### ② 搞清楚"项目在哪里"

这个项目是一个**文件夹**，里面有 `docs/`、`simulators/`、`training/` 这些子文件夹。

**你要做的第一件事**：在终端里"走进"这个文件夹。命令是 `cd`（change directory 的缩写）：

```bash
cd 你的项目路径
```

比如你的项目在 `C:\Users\sen.kang\Desktop\文档\项目\兴趣\robot_framework`，就输入：

```bash
cd "C:/Users/sen.kang/Desktop/文档/项目/兴趣/robot_framework"
```

> 💡 **怎么确认成功了**？输入 `ls`（list）按回车，你应该看到一列名字：
> `docs  simulators  training  scenarios  README.md ...`
> 看到这些，说明你已经在项目里了。

### ③ 确认"工具"都装好了

输入这一行，按回车：

```bash
python training/check_all.py
```

**你应该看到**（最后一行）：
```
 结果：12/12 个练习的参考答案通过
```

看到这句话，说明**环境**是好的，可以开始 D1 了。

> ⚠️ 注意：这里验证的是 12 个**参考答案**能不能跑通，**不是给你的练习判分**。
> 你每天自己写的 `exercise.robot` 要单独跑（各自的 README 里有命令），看到 `PASS` 才算通过。

**如果报错**：
- `python: command not found` 或 `'python' 不是内部或外部命令`
  → 试 `py training/check_all.py`（Windows）或 `python3 training/check_all.py`（Mac）
- `ModuleNotFoundError: No module named 'xxx'`
  → 依赖没装，去看 [docs/06 章 6.1 节](../docs/06_环境搭建与项目结构.md) 装一下
- `No such file or directory`
  → 你不在项目文件夹里，回到第 ② 步

## 🎓 走完 7 天后的"毕业任务"（1-2 天，做完你就真能干活了）

7 天是"会跑"，这个任务才是"**能独立完成一次系统验证**"。

### 为什么给你这个任务

D7 里你看到覆盖率是 **96.5%，其中 DTC 覆盖 3/5** —— 有 2 个故障**从来没被测试过**。
其中一个就是 **P0117（水温过低 / 传感器对地短路）**。

**这就是真实工作**：覆盖率工具告诉你"这里有个洞"，你要去把它补上。

### 任务：补上 P0117 的测试

**需求（客户提的）**：

> 水温低于 **-30℃**（传感器对地短路）时，ECU 应记录 **P0117**，并点亮**水温报警灯**。

**你要做的六步**：

| 步骤 | 做什么 | 怎么做 |
|---|---|---|
| ① 写需求 | 在需求清单加一条 | `requirements/requirements.yaml` 里加 `REQ-DTC-007`（照现有格式抄） |
| ② 写用例 | 新建一个 `.robot` | `scenarios/13_water_temp_low.robot` |
| ③ 造场景 | **启动时**把水温设成 -40 | `Suite Setup    Start Vehicle Environment    coolant=-40` |
| ④ 写断言 | 等 P0117 + 确认灯亮 | 见下方"关键提示" |
| ⑤ 打标签+追溯 | 登记关系、看矩阵 | 见下方"第 5 步怎么做"：改 `link_requirements.py` 里的 `MAPPING` |
| ⑥ 出报告 | 跑全量看覆盖 | `python run_tests.py --report` |

### 关键提示（照着写就能过）

```robotframework
*** Settings ***
Resource         resources/common.resource
Suite Setup      Start Vehicle Environment    coolant=-40    # ← 关键：启动时就设低温
Suite Teardown   Stop Vehicle Environment

*** Test Cases ***
水温过低应记录 P0117 并点亮水温灯
    [Tags]    REQ-DTC-007
    Wait Until Keyword Succeeds    25x    1s    DTC List Should Contain    P0117
    ${lit}=    Get Lit Telltales
    Should Contain    ${lit}    CoolantTempHigh
```

> ⚠️ **为什么必须等 20 秒以上**：水温从 90℃ 降到 -30℃ 是**一阶惯性过程**（约 10 秒），
> 再加上"连续 2 个诊断周期确认" → 总共 12~15 秒。这就是 D4 学的"按物理过程定超时"。

### 第 5 步怎么做（这一步骤最容易卡住，写清楚）

打开 `link_requirements.py`，找到第 35 行左右的 `MAPPING = {`，
在 `MAPPING` 字典内部**任意两个条目之间**插入即可（例如紧接
`"scenarios/12_power_management.robot": {...},` 这段之后；注意 `MAPPING` 的最后一项其实是
`tests/robot/06_uds_flash_conformance.robot`，所以"最后一项之后"应理解为 `MAPPING` 结尾的 `}`
之前一行）：

```python
    "scenarios/13_water_temp_low.robot": {
        "水温过低应记录 P0117 并点亮水温灯": ["REQ-DTC-007"],
    },
```

> 💡 格式说明：**`"文件路径": { "用例名": [需求ID, ...] }`**。
> 文件路径是**相对项目根目录**的（`scenarios/13_...`），用例名必须和 `.robot` 里写的一字不差。
> 加完保存，然后跑：
> ```bash
> python link_requirements.py --dry-run    # 先看它会做什么（不写入）
> python link_requirements.py              # 真正写入（给你的用例打上 REQ-DTC-007 标签）
> python trace_matrix.py                   # 看矩阵里有没有你的需求
> ```

**完成标准**：
1. 你的用例 PASS
2. `trace_matrix.html` 里 `REQ-DTC-007` 显示"✅ 已覆盖"
3. `coverage.html` 里 DTC 覆盖从 **3/5 变成 4/5**
4. 你能说清"为什么这个测试之前没人做"（因为需要特殊工况，容易被漏）

> 💡 **做完这个任务，你就完整走过了**：需求 → 用例 → 执行 → 追溯 → 报告 这条链。
> 这就是"系统性完成汽车自动化测试"的样子。

> 📖 方法论参考 [docs/20 章](../docs/20_测试规范与验证交付物.md)，模板在 [deliverables/](../deliverables/)。
