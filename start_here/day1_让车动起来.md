# D1 · 让一辆车"跑起来"（40 分钟）

> **今天只有一个目标**：亲眼看到一辆虚拟的车动起来。
>
> 你不需要懂任何技术。今天做的事，就像"打开一个游戏，看看画面"。

---

## 为什么先做这个？

你以后的工作是**测试汽车上的电子设备**（比如仪表盘显示对不对）。

但你从没见过这些设备，也不知道它们长什么样 —— **所以先让你看一眼**。

看完你会明白：**"哦，原来我以后要测的是这个东西。"**

---

## 第 1 步：打开两个"黑框框"

### 什么是"黑框框"

就是**终端**（Terminal）。你在里面打字，电脑就执行。

**怎么打开**：
- Windows：`Win` 键 → 输入 `git bash` 或 `cmd` → 回车
- Mac：`Command + 空格` → 输入 `terminal` → 回车

**打开后会看到**：一个窗口，里面有一行字，后面一个闪烁的光标。

**今天你要开两个**（因为要同时跑两个程序）：
1. 先开一个 → 这就是"终端 1"
2. 再开一个（同样的方法）→ 这就是"终端 2"

> 💡 两个窗口可以在屏幕上并排摆着，方便看。

---

## 第 2 步：进入项目文件夹（两个终端都要做）

**在两个终端里分别输入下面这行**（把路径换成你电脑上的实际路径），按回车：

```bash
cd "C:/Users/sen.kang/Desktop/文档/项目/兴趣/robot_framework"
```

> 💡 **不确定路径？** 在文件管理器里找到 `robot_framework` 这个文件夹，
> 点进去，然后点地址栏，就能看到完整路径，复制过来。

**输入后按回车**。然后输入 `ls` 按回车，**你应该看到**：

```
README.md   docs   libraries   requirements.txt   scenarios   simulators   start_here   tests   training
```

看到这一堆名字 = **你已经在项目里了** ✓

> ⚠️ 如果看到 `No such file or directory`：说明路径不对，检查一下有没有打错字、
> 有没有漏掉引号。

---

## 第 3 步：在"终端 1"里，让车跑起来

输入这一行，按回车：

```bash
python simulators/ecu_sim.py --speed 60
```

**你应该看到**（类似这样）：

```
==============================================================
 动力域 ECU 模拟器已启动
 周期报文: 0x100(100ms) 0x200(200ms) 0x300(500ms)
 诊断监听: 0x7E0 请求 → 0x7E8 响应
 控制命令: status | dtc | speed <n> | coolant <n> | inject <DTC> | unject <DTC> | help | quit
==============================================================
2026-10-17 ... ECU 主循环运行中
```

**看到这些，说明"一辆车"已经在你的电脑里启动了**。

> 🔴 **重要**：这个窗口**不要关**！
> 关了车就"熄火"了。它要一直开着，等你做完今天的实验再关。

**现在这辆车是什么状态？**
- 它设定了一个目标车速：**60 km/h**
- 它正在以**每秒 8 km/h** 的速度慢慢加速
- 它一直在"说话"（周期发报文）—— 但现在没人听

---

## 第 4 步：在"终端 2"里，让仪表盘亮起来

**切换到终端 2**（点一下那个窗口），输入：

```bash
python simulators/dashboard.py
```

按回车。

**你应该看到**：**弹出一个窗口**，里面是一个数字仪表盘！
（黑色的、有圆形表盘、有数字）

盯住**左边的车速表**看 10 秒 —— 你会看到**指针从 0 慢慢爬到 60**。

**同时你还能看到**：
- 右边的转速表：从 0 涨到 4800 左右（它和车速是联动的）
- 中间的档位：显示 `D`（D = 前进档）
- 下面的水温、油量、里程

> 💡 **这就是你以后要测的"被测对象"**。真实车上它长这样，你现在看到的是仿真版。

---

## 第 5 步：玩一下（3 分钟）

**别急着往下走，先随便玩玩**，建立"这东西是活的"的感觉：

1. **等 8 秒**，看指针停在 60（稳定了）
2. **切到终端 1**（车那个窗口），输入 `speed 120` 按回车 → 再切回仪表看，指针会慢慢爬到 120
3. **输入 `speed 0`** → 指针慢慢回到 0
4. **输入 `status`** → 车会告诉你它现在的状态

> 这些命令在终端 1 的启动信息里都列出来了（`speed <n> | status | dtc | help`）。

---

## 第 6 步：收工（关掉它们）

1. 在**终端 2**（仪表）按 `Ctrl + C` → 窗口关闭
2. 在**终端 1**（车）按 `Ctrl + C` → 车熄火

> 💡 `Ctrl + C` 的意思是"强制停止当前程序"。记不住就记：**跑完的程序用 Ctrl+C 结束**。

## ✅ 今天的验收标准

不看文档，回答这三个问题（能答出来就算过关）：

1. **你刚才看到的那个窗口里，指针动起来是因为什么？**
   （提示：终端 1 里那个程序在"开车"）
2. **转速表为什么跟着车速一起涨？**
   （提示：真实车里它们有固定的比例关系 —— 不知道也没关系，D3 会讲）
3. **仪表显示 `D` 是什么意思？**
   （提示：P 停车、R 倒车、N 空挡、**D 前进**）

## 🆘 卡住了怎么办

| 你看到的现象 | 原因 | 怎么办 |
|---|---|---|
| `python: command not found` | 系统里没有 `python` 这个命令 | 试 `py simulators/ecu_sim.py --speed 60`（Windows）；或 `python3 ...`（Mac） |
| `No module named 'PySide6'` | 图形界面库没装 | 用无界面模式：`python simulators/dashboard.py --headless`，然后**看不了窗口**，直接跳到 D2（不影响） |
| 仪表窗口打开了但**指针不动** | 终端 1 的车没启动 / 被关了 | 确认终端 1 还在跑（有日志在滚动），如果关了重新开 |
| 仪表窗口**一片黑** | 可能需要几秒初始化 | 等 5 秒；还不行就 Ctrl+C 重开 |
| 车速一直显示 0 | 目标车速是 0 | 切到终端 1 输入 `speed 60` |

## 📌 今天你学到的事（用大白话）

1. **"终端"就是跟电脑说话的地方**，输入命令按回车，电脑就干活。
2. **这个项目里有"一辆车"和"一块仪表"两个程序**，要分别启动。
3. **仪表上的数字不是随便编的** —— 它是从"车"那里实时收来的。
4. 你以后的工作 = **验证"仪表显示的数字，和车真实的状态对不对得上"**。

> 术语对照（现在不用记，以后会反复遇到）：
> - 那个"车"的程序，行业里叫 **ECU**（车上的小电脑）
> - 它们之间"说话"的方式，叫 **CAN 总线**
> - 你看到的仪表，叫 **Instrument Cluster**
