## 二、完整改动（3 个文件 + 2 条命令）

### 步骤 1：加需求（`requirements/requirements.yaml`）

在 `REQ-DTC-006` 之后、`# ---- 刷写` 分节之前插入：

```yaml
  - id: REQ-DTC-007
    title: 水温过低故障检测（传感器对地短路）
    description: 冷却液温度低于 -30℃（传感器对地短路）时，ECU 应记录 P0117 并点亮水温报警灯
    source: SRS-7.6.1
    priority: High
    method: Test
    verify: 低温启动（coolant=-40）后等待物理过程与诊断确认周期，断言 P0117 存在且水温灯点亮
```

### 步骤 2：写用例（`scenarios/17_water_temp_low.robot`）

```robotframework
*** Settings ***
Documentation    毕业任务：P0117 水温过低（传感器对地短路）
...              水温从 90℃ 向 -40℃ 一阶惯性下降（时间常数约 4s），
...              越过 -30℃ 阈值后需连续 2 个诊断周期才 confirmed（约 10~15s）。
Resource         ../resources/common.resource
Suite Setup      Start Vehicle Environment    coolant=-40    # 关键：启动时就设低温
Suite Teardown   Stop Vehicle Environment

*** Test Cases ***
水温过低应记录 P0117 并点亮水温灯
    [Tags]    dtc    hmi    REQ-DTC-007
    [Documentation]    DTC 状态机：先 pending 后 confirmed；灯由 DTC 驱动，
    ...              所以"等 P0117 + 断言灯亮"是同一个闭环的两端。
    Wait Until Keyword Succeeds    25x    1s    DTC List Should Contain    P0117
    ${lit}=    Get Lit Telltales
    Should Contain    ${lit}    CoolantTempHigh
    ...    msg=P0117 已确认但水温报警灯未点亮：诊断与仪表联动断裂
```

> 说明：`DTC List Should Contain` 来自 `DiagnosticLibrary`，`Get Lit Telltales` 来自
> `DashboardLibrary` —— 两者都已由 `resources/common.resource` 导入，不需要额外 `Library` 行。

### 步骤 3：登记追溯（`link_requirements.py` 的 `MAPPING`）

在 `MAPPING = {` 内任意两个条目之间插入（例如紧跟 `scenarios/12_power_management.robot` 段之后）：

```python
    "scenarios/17_water_temp_low.robot": {
        "水温过低应记录 P0117 并点亮水温灯": ["REQ-DTC-007"],
    },
```

格式：`"相对项目根目录的文件路径": { "用例名": [需求ID, ...] }`。

### 步骤 4：跑起来（按顺序）

```powershell
# ① 先只跑你的新场景（确认用例本身能过；约 15 秒）
python -m robot --outputdir results scenarios/17_water_temp_low.robot

# ② 先 dry-run 看追溯工具会干什么，再真正写入标签
python link_requirements.py --dry-run
python link_requirements.py

# ③ 看追溯矩阵里 REQ-DTC-007 是否"已覆盖"
python trace_matrix.py

# ④ 重跑全量 + 报告，看 DTC 覆盖率变化（约 6 分钟）
python run_tests.py --report
```

## 四、常见卡点（对号入座）

| 现象 | 原因 | 解决 |
|---|---|---|
| `P0117` 一直等不到 | 温度降不到 -30℃ / 没设 `coolant=-40` | `Suite Setup` 传参；等待上限 ≥20s |
| 灯不亮 | 只查了 DTC 没查灯，或仪表未同步 | 确认 `Get Lit Telltales` 返回值；灯由 0x300 报文驱动，需等一拍 |
| `link_requirements.py` 提示用例名不匹配 | 文件名/用例名写错（含空格全角） | 与 `.robot` 里**一字不差**；路径相对项目根目录 |
| 覆盖率数字没变 | 跑的是旧的 `results/output.xml` | 先跑全量（或至少跑包含该场景的测试）再执行 `coverage_report.py` |
| 和别的测试一起跑失败 | 项目共享虚拟总线，**不能并发跑** | 一次只跑一个 robot/全量回归（见 KNOWN_ISSUES） |

## 五、做完之后问自己三件事（面试会问）

1. 为什么这个测试之前没人做？（需要特殊工况/低温箱或传感器短路，普通用例覆盖不到 → 覆盖率盲区的典型来源）
2. 为什么用 `Wait Until Keyword Succeeds` 而不是 `Sleep 15`？（等待物理过程：到点即过、机器慢会自动等；`Sleep` 写死时间要么慢要么偶发失败）
3. 如果 P0117 的阈值从 -30℃ 改成 -20℃，哪些地方要改？（需求描述/verify、用例启动温度/等待策略、可能还要同步测试规范 —— 这就是"需求变更影响分析"）
