# D5 · 跟车"对话"（70 分钟）

> **今天做的事，就是 4S 店维修工做的第一件事**：插上电脑，问车几个问题。
>
> 你会亲手读出：这辆车的型号、车架号（VIN）、以及"它有没有毛病"。

---

## 先说清楚：什么叫"跟车对话"

你去 4S 店保养，维修工会拿一个平板/小盒子插到方向盘下面的接口上。

那个动作在干嘛？**在跟车里的电脑"对话"**：

```
维修工：  "你是什么型号？"      → 车："我是 HW-IC-2026-001"
维修工：  "你的车架号是多少？"    → 车："LSVAM4180NC000001"
维修工：  "你有故障吗？"          → 车："有，P0116（水温传感器）"
```

**这套"问答规则"有个名字，叫 UDS**（不用记，知道有这么个东西就行）。

**它和你平时写代码调 API 一模一样**：

| 网络 API | 车上的诊断 |
|---|---|
| 你发一个 `GET /user/1` | 你发一句 `22 F1 90`（读 VIN） |
| 服务器返回 JSON | 车返回一串十六进制 |
| 404 / 500 | 车回 `7F ... 31`（我拒绝，参数超范围） |

> 🎯 **所以你今天要学的新东西只有一个**：**怎么发"请求"、怎么看"响应"**。
> 这部分你其实已经会（就是"发消息、收消息"）。

---

## 第 1 步：启动"车"和"诊断仪"

开**两个终端**（都在项目根目录）。

**终端 1 —— 启动车**：

```bash
python simulators/ecu_sim.py --speed 60
```

**终端 2 —— 启动诊断仪**：

```bash
python simulators/uds_client.py
```

**你应该看到**（终端 2）：

```
命令:
  裸 hex          直接发 UDS 请求, 如 10 03 / 22 f190 / 19 02 08 / 14 ff ff ff
  session <def|ext>   会话切换
  read_did <DID>      读 DID
  ...
uds>
```

看到 `uds>` 这个提示符 = **诊断仪连上了，在等你输入命令**。

---

## 第 2 步：读零件号（最简单的对话）

在 `uds>` 后面输入：

```
22 f187
```

按回车。**你应该看到**：

```
→ 正响应 SID=0x62 payload=f18748572d49432d323032362d303031
```

**这串东西怎么读**：

| 部分 | 意思 |
|---|---|
| `正响应` | 车同意回答（如果显示 `负响应 NRC=0x..` 就是拒绝了） |
| `SID=0x62` | 响应的"服务号"（`22` 是请求，响应就是 `22 + 0x40 = 0x62`） |
| `payload=f187...` | 真正的数据：前 4 位 `f187` 是"你问的编号"（原样回给你），后面是答案 |
| `48572d49432d...` | 答案的**十六进制**。每 2 位是一个字符的 ASCII 码：`48`=H `57`=W `2d`=`-` … 拼起来是 `HW-IC-2026-001` |

> 💡 工具只显示十六进制，**不会自动翻译成文字** —— 你要自己对着 ASCII 表看。
> （也可以把 `48572d...` 粘给任意"hex 转 ASCII"的在线工具）

> 💡 **这就是"读数据"的全过程**：你问编号 → 车答内容。
> 编号（`F187`）在行业里叫 **DID**（Data Identifier）。

---

## 第 3 步：读车架号（VIN）

输入：

```
22 f190
```

**你应该看到**：

```
→ 正响应 SID=0x62 payload=f1904c5356414d343138304e43303030303031
```

比上次**长很多**（因为 VIN 有 17 个字符）。

> 💡 17 个字符 = 17 字节，一帧最多装 7 字节 → 装不下，所以**实际总线是分好几段传的**
> （这个机制叫 ISO-TP）。**但工具帮你自动重组了，你看到的是一条完整的响应。**
> 知道"长数据要分包"就够了，细节在 [docs/03 章 3.6](../docs/03_UDS协议详解.md)。

---

## 第 4 步：问它"有故障吗"

输入：

```
19 02 ff
```

**你应该看到**：`无故障`（或空列表）。

> 💡 `19` 是"读故障码"的命令，`02` 是"按状态筛选"，`FF` 是"全都要"。
> **现在没有故障，所以是空的** —— 明天（D6）你会让它有故障，再看一次。

---

## 第 5 步：试试"被拒绝"（理解权限）

有些操作不是随便能做的。试试写入一个值：

```
2e f1a0 56332e302e30
```

（意思是"把 `F1A0` 这个编号的值改成 `V3.0.0`"）

**你应该看到**：

```
← 7F 2E 7F
  负响应 NRC=0x7f（当前会话不支持该服务）
```

**别慌，这是对的。** 车在说："**默认状态下我不让你改东西**。"

想改？要走两道门：

```
10 03      ← 门 1：进入"扩展会话"（工作模式切换）
27 01      ← 门 2：请求"种子"（车给你一个随机数）
27 02 ...  ← 门 2：按算法算出"密钥"发回去
2e f1a0 ...← 现在才能写
```

> 💡 这个"种子-密钥"的过程，工具里有个快捷命令：`unlock`（自动完成握手）。
> 你可以在 `uds>` 里依次试：`session ext` → `unlock` → 再发一次 `2e ...`。

**为什么要这么麻烦？** 因为车是**安全相关设备** —— 不能让任何人插个设备就能改刹车参数。

## 第 6 步：看一眼"自动化的版本"

你刚才手工做的事，项目里已经写成自动化用例了。

打开 [`tests/robot/02_uds_diagnostic.robot`](../tests/robot/02_uds_diagnostic.robot)，
**只看前 3 个用例**（不用全懂），你会发现：

```
默认会话下应能读取 DID
    ${did}=    Read DID    F187
    ...
```

**这就是"手工操作 → 自动化脚本"的翻译**：

| 你手工敲的 | 脚本里写的 |
|---|---|
| `22 f187` | `Read DID    F187` |
| `19 02 ff` | `Read DTC By Mask    FF` |
| `session ext` | `Enter Extended Session` |
| `unlock` | `Security Unlock` |

> 🎯 **这就是这行的核心工作**：把"老师傅手工做的操作"翻译成**能重复跑的脚本**。

## ✅ 今天的验收标准

1. 能说清 **"诊断"是什么**（你问一句，车答一句，有固定格式）
2. 能说出 **`22` 是读、`2E` 是写、`19` 是读故障、`10` 是切会话**
3. 能解释 **为什么写操作会被拒绝（`7F`）**
4. 能说清 **"种子-密钥"是干嘛的**（证明你有权限，不是谁都能改）
5. 能说出 **"手工敲命令"和"脚本"的对应关系**

---

## 🆘 卡住了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `uds>` 输入后没反应 | 车没启动 / 总线不通 | 确认终端 1 在跑（有日志）|
| 响应超时 | 车没在监听 | 重启终端 1 |
| 输入 `22 f187` 报格式错 | 大小写/空格问题 | 用 `22 F187` 或 `read_did F187` 也行 |
| 想退出 | — | 输入 `quit` 或按 `Ctrl+C` |

---

## 📌 今天你学到的事

1. **诊断 = 有固定格式的问答**（请求 `SID+参数`，响应 `SID+0x40+数据` 或 `7F+NRC`）
2. **DID** 是"数据编号"（`F187` 零件号、`F190` VIN）
3. **写操作有权限门槛**（会话 + 种子密钥），因为车是安全设备
4. **自动化脚本就是把手工命令翻译成代码** —— 你已经在做这件事了

> 术语补充（以后会反复遇到）：
> - 那套问答规则叫 **UDS**（统一诊断服务）
> - "我拒绝"的响应码叫 **NRC**（`0x7F` = 当前会话不支持、`0x33` = 没权限）
